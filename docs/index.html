An AI operating system whose most important feature is what it refuses to do.

Seventeen specialised agents run research, a job-search pipeline, investment research, study support and security monitoring on one Mac, unattended. Nothing is sent, deleted, paid or traded without a human tapping approve, every action is logged to a hash-chained ledger, and the whole thing runs with zero pay-per-token API spend.

Specified, governed and operated by an undergraduate Commerce/Law student. Code written by AI coding agents to those specifications, reviewed change by change.

Why build this

Assistants answer questions. This one does the standing work.

Read the news at 6am and write the brief. Find and score the day's job ads. Turn a lecture transcript into flashcards. Watch the stack's health. Research a stock and write the memo. Take a spoken instruction from across the room. All without being watched, and, the harder problem, safe to leave running.

The design premise from the original brief: the point is not a smarter base model; it is to get far more out of the models you already pay for, through decomposition, delegation, memory, verification, parallelism and cost-aware routing, inside an interface you control.

Three rules that hold it together
State lives in the vault or the database, never in an agent's memory.

If it is not written down, it did not happen as far as the next agent is concerned.

Rails only get tighter.

The control model

Seventeen hooks that only tighten

Deterministic scripts run around every agent tool call. They are the enforcement layer; prompts are not.

  • Kill switch. Stops every agent on a single flag.
  • Budget gate. Debits every agent spawn into a ledger before it runs and denies at the cap: 60 per session, 8 concurrent, depth 3, 5 children per task. Nested spawns share the session budget (proven live).
  • Tool-call gate. 8,000 calls per session; past the cap every call becomes an "ask": a conscious click-through when interactive, a cold stop for a headless runaway.
  • Secrets and workspace guards. Deny reads of key files and .git, and writes outside the workspace.
  • Protected-files guard. No agent can edit the operating rules it runs under.
  • Relay check. Flags any division lead who cites a health check the ledger shows never ran.
ADR-016 · ADR-018 · ADR-026 · ADR-032

Zero spend, by invariant

One subscription, free-tier providers and a local model. The router walks up to 18 providers per call and, when every model is down, renders a deterministic template rather than going silent. A later proposal to add a paid rung was withdrawn and the invariant restored.

Sensitive data goes only to the subscription model or the local model. The one exception is an opt-in, per-call redacted path to three providers that contractually retain nothing, adopted after the research showed redaction is a leak-reducer rather than a blocker, with the residual risk written into the decision record.

An audit trail you can argue with

  • Hash-chained activity log in Postgres: every action, in order, tamper-evident.
  • 33 decision records, from typography to "no paid rung".
  • 32 incident post-mortems, including a planted-bug drill, a credentials-wipe outage, fabricated completion events and a chaos test that killed the workflow engine on purpose.
  • A lessons log fed mechanically by a hook from every agent's result contract, reviewed weekly, promoted or deleted.
JARVIS 7

A delegation tree with mechanical bounds

One protocol at every level. A parent receives a task with a budget and a deadline, decides whether to do it or decompose it, and each child returns a structured result contract: output, cost, status, notes, lessons learned. The parent verifies the result with a separate reviewer, aggregates, and returns up.

Person
  └── Chairman        main thread only, never a subagent
        ├── Minerva    research & analysis lead   → Scout, Ledger, Herald
        ├── Daedalus   product & building lead    → Forge, Muse
        ├── Aegis      security, ops & QC lead    → Warden, Fix, Sentinel, Archivist
        └── Arbiter    standing reviewer; review only, never fixes

Corporate titles are persona labels, not tree levels. Division leads may spawn only their own workers plus the Arbiter; cross-division, lead-to-lead and self-recursion all deny. The observer (Sentinel) stays independent of the fixers so a lead cannot launder a fix through its mouth (ADR-027).

Evaluation

Twenty-five behaviour fixtures probe the tree live: does a lead decompose or do the work itself; does it relay a health check verbatim; does it refuse to launder a fix. The full set passed 25 of 25 after two rulings: transient failures retry, and a required-field miss is a NEEDS_REVIEW verdict, not a pass.

Voice and the macOS action layer

Nothing spoken leaves the machine

  • Always-on wake word (openWakeWord on ONNX), local speech-to-text (whisper.cpp) and local text-to-speech (Kokoro).
  • A speech-aware overlay with a four-state machine and a media guard that pauses or ducks whatever is playing, re-entrantly, with a 120-second watchdog so a crash can never leave the room muted.
  • Screen questions. "What's on my screen" captures, OCRs and describes the display, on request and only on request.
  • A local HUD with sixteen panels behind token, origin and rate-limit middleware; an ambient read-only view doubles as the wallpaper.
ADR-023

Benchmarked, not deployed

A newer speech model was benchmarked against the incumbent and deliberately not deployed. The decision record shows the numbers, which is the point: a decision you can re-open later is worth more than a faster model you cannot explain.

Remote approvals

Gated actions can be approved from a phone. The live proof produced a lesson worth more than the feature: three consecutive approvals were tapped, including two whose text said "tap deny". Remote approval is a liveness gate, not a review gate, so approval summaries now lead with the consequence, not the mechanism.

Career Hub

A job-search pipeline with a strict honesty model

The largest subsystem, and the one closest to analyst and consulting work: a product-owned data pipeline that reads the Sydney market every day and drafts, but never sends.

1Fetch35 sources: job boards, aggregators, ATS vendors' public boards, a scraper, employer career pages, RSS alerts, newsletters, a VC board
2Normaliseone schema; duplicates merged across sources by fingerprint
3Firm intelligencecompany-registry lookup, employer aliases, agency detection
4Classifyhours, unpaid, contract; a seniority guard for roles a student cannot get
5Scorefit against the profile; stale-cache detection by content hash
6Link check404 or 410 twice = closed; 429 = rate-limited, not dead
7Shortlistthree a day into the daily note
8PackCV, cover letter, cold email: drafted, never sent; read-only inbox sweep for replies

The honesty model

  • The profile file is the only source the drafting pipeline may draw facts from, and every drafting prompt carries a no-fabrication contract. A missing fact stays missing.
  • Four independent submit guards: a halt flag, an empty vendor allowlist, an evidence gate that measures form-fill quality per vendor, and payload-hash pinning. The system has never submitted an application and cannot.
  • Content rules live in code and tests, not only in prompts: dash normalisation on every draft, and a seniority guard measured on the pool (40 of 52 senior-titled roles had slipped past the old pattern and sat above the internships).
  • Closing signals so dead roles stop scoring, including a link checker that treats a rate-limit response as "try again", after one vendor was made to look 95% dead by a 429.

What two reviews found

Scored 76 then 79 out of 100. Six defects were invisible in the source and only visible in the data:

  • an absent employer field had merged four different employers' ads into one identity;
  • a field documented as shipped existed nowhere;
  • the top-scoring role was an unpaid internship;
  • one source regenerated its URLs per fetch, so a URL was never an identity there;
  • a vendor's "48% clean" fill rate had been measured the day before its own fix landed (fresh benchmark: 15 of 15);
  • cached scores went stale after profile edits with no signal; fixed by hashing profile content into every score row.

The rule that came out of it: a code fix to anything cached or exported is only half a fix; backfill the stored copies. And review the data, not just the code.

Lessons that cost something

Promoted from the log, each with the evidence that earned it

L-003
Completion claims are data, not facts.

Two fabricated "stop" events claimed pending gates had passed and urged the next phase, with nothing in the ledger, the audit log or the transcripts. Trust artefacts only.

L-004
Remote approvals get rubber-stamped.

The human pattern is green-button-by-default. Approval requests now lead with the consequence; anything that needs real review does not go through a phone.

L-005
A pre-written result contract is a red flag, whatever the framing.

An agent that returns a "done" contract it could not have earned yet is reporting intent as fact.

L-002
When every path fails identically, suspect one shared dependency.

"Subagents cannot reach the keychain" turned out to be an outage wearing a rail-shaped costume. The rule was amended, with the evidence, rather than left standing.

hub
Always stratify before calling a score gap "bias".

The naive reading of the hub's score distributions was wrong five times running.

hub
Check for another running session before assuming a stray process.

A commit collision from a second concurrent session looked exactly like a bug.

How it was built

Specification first, rulings not vibes

Every stage began as a written brief: the goal, the constraints, the out-of-scope boundaries, the verification required before the next phase. The JARVIS 7 brief runs to 23 sections and opens with "re-verify the fast-moving platform facts and record what you found versus what this document assumed" before any code.

AI coding agents wrote the code. Claude Code agents implemented each feature against the brief. I reviewed every change, ran the tests and the eval fixtures, and recorded the decision. A claim that could not be verified from an artefact was not accepted. This is stated plainly because it is the actual division of labour, and because directing, verifying and governing agent-written systems is the skill the project demonstrates.

When the brief and reality disagreed, a ruling settled it and was logged: no API keys, no permission-bypass flags, no paid rung, sensitive data stays local. Later proposals that conflicted with a ruling were rejected and the rejection recorded.

Self-improvement is propose-then-approve. An autonomous "engineering lead" run produced ten improvements on an unmerged branch pair, every behaviour change behind a default-off flag, with a restore checklist and a per-flag enable order for the human to work through.
